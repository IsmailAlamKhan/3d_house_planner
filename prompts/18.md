# Prompt 18 — Reference Villa: Trace From the Picture and Build It 1:1

## Why this prompt exists
The owner's wife wants **the villa in `reference/villa-reference.png`** as a navigable 3D model. The AI solver tiles rooms automatically, so it can never reproduce a specific plan. The villa made earlier ("Luxury Villa (reference plan)") was built by a throw-away script that isn't in the repo, and it is only an approximation (see PROGRESS.md, OPEN 3).

This prompt adds:
- a **reference-image underlay** for tracing,
- a **committed, data-driven reference spec**,
- a **deterministic exact builder** (no treemap or solver),
- and builds this villa faithfully, as two design options.

**Make this prompt idempotent.** Reuse the existing villa/site mode, design options, catalog, and checks. Nothing in this prompt may live only on the server or in throw-away scripts: everything is committed and reproducible with one command.

## Part 1 — Reference image underlay (2D editor)
1. **Import an image** (PNG, JPG, WebP) per project or level as an underlay. Store it as an asset via `/api/assets` (with an IndexedDB fallback on static hosting).
2. **Perspective rectification:** the reference is shot from a slight angle. The user clicks the 4 corners of a known rectangle (for example the plot boundary) and enters its real size. A homography rectifies the image onto the plan. Also offer a simple 2-point mode: two points plus a known distance.
3. Controls: opacity, show/hide, lock, move, rotate, and "send to back". Show the underlay in 2D, and optionally as a faint ground decal in 3D top view.
4. Tracing works with the existing wall, room, zone, and gate tools, snapping to the underlay is not required. Add a **"Measure from image"** readout that shows real-world lengths under the cursor.

## Part 2 — Reference spec format and exact builder
1. **`src/reference/spec.ts`:** a Zod schema for a human-editable `ReferenceSpec`:
   - plot polygon, building outline, units (ft or m), and level heights;
   - **rooms as rectangles or polygons with exact positions**, plus name, type, floor material, wall finish, and label text;
   - shared walls (derived), openings (door and window type, wall side, offset), glass partitions;
   - outdoor zones (lawn, deck, paving, pool with organic outline, planting beds) and gates;
   - boundary wall with pillars and lights;
   - **items** (catalogId or asset id, position, rotation, size, and props such as bedding color);
   - lights (type, position, on/off per preset);
   - and the camera views to save.
2. **`src/reference/build.ts`:** a deterministic builder that turns a spec into project operations **exactly**, with no solver and no treemap. It applies as one undoable batch, and reports overlaps, gaps, and unreachable rooms through the existing checks.
3. **Export the current project back to a spec** (`Export → Reference spec (.json)`), so a hand-corrected design can be saved as a spec.
4. Add an npm script, `npm run reference:build -- reference/villa.spec.json`, that builds the project and saves it to the server (or to a file with `--out`). This replaces the earlier throw-away script.

## Part 3 — Build THIS villa (`reference/villa.spec.json`, committed)
Copy `reference/villa-reference.png` into the repo, then trace it with the underlay and record the result as a spec.

**Two versions, as design options in one project, "Reference Villa":**
- **Option A "As labelled":** every labeled room has exactly its labeled size. The layout (rows, wings, adjacency, what is next to what) follows the picture. Leftover space becomes corridors, planting strips, or wall thickness.
- **Option B "As pictured":** proportions are measured from the rectified picture, calibrated so the Covered Car Parking is 20 ft wide. Labels in the app show the modeled sizes, not the picture's numbers.

**Fidelity report** (`reference/FIDELITY.md`, generated by the build script): a table with one row per element, showing the labeled size, the size measured in the picture, and the modeled size in Options A and B, with notes on every deviation.

## Part 4 — Side-by-side comparison
Add a **Compare with reference** view: the reference image next to the app's "Reference top-down" render, with a draggable split slider and a matching camera. It is the main tool for judging fidelity.

## Acceptance criteria
- `npm run reference:build -- reference/villa.spec.json` recreates the project from a clean database, with both options.
- Every element in the inventory exists in both options, and `FIDELITY.md` lists all of them.
- In Option A, every labeled room matches its label to within 1 inch.
- Option B overlaid on the rectified picture at 50% opacity lines up wall-for-wall: every room outline within 0.5 ft.
- The walkthrough works from the pedestrian gate through the foyer into every room, the pool deck, the gym, and up to the roof terrace.
- Checks report no unreachable rooms.
- Unit tests cover the spec schema, homography, and the builder (including the overlap and gap report).

# Prompt 15 — Presentation Renders & Local AI Image Enhancement

## Goal
Let users produce glossy "magazine-style" images of their design: a top-down cutaway or 3/4 view at dusk, with warm lights, decor, plants, and crisp room labels. Then optionally make the image photoreal with a free, local image AI running on the same GPU.

There are two layers:
- **(A) Presentation mode.** Exact and deterministic: it shows the real design.
- **(B) AI enhancement.** A mood image: it may change details, and is always labeled as such.

**Make this prompt idempotent.** If any of this already exists, update it rather than duplicating it.

---

## Part A — Presentation mode (inside the app, no AI)

1. **Render presets** (a new "Present" tab or toolbar mode):
   - **Cutaway top-down:** an orthographic or near-orthographic view from above. Hide ceilings and the upper slab, cap walls at their cut height with a clean top color, and isolate the chosen level (or upper level over lower level, offset).
   - **Cutaway 3/4:** a perspective view at about 50–60° from horizontal, same cutaway.
   - **Eye-level:** use any saved view from prompt 9.
   - Each preset frames the active level automatically, with a margin.
2. **Lighting looks:** Dusk (warm interior lights on, blue-hour sky, warm path and accent lights), Daylight, and Night.
   - Interior light items emit warm light. Add automatic "accent" lights (cove, under-cabinet, path) as a toggle.
   - Post-processing (the `postprocessing` library): bloom on emissive surfaces, SSAO, tone mapping (ACES), slight vignette, and FXAA/SMAA.
3. **Path-traced stills:** a "High quality still" button that uses `three-gpu-pathtracer` (pin an exact version) to progressively render the current preset.
   - Show the sample count and progress, and stop at a configurable target or on cancel.
   - Fall back to the rasterized presentation render if the path tracer fails or the GPU is too weak.
4. **Room labels overlay:** room name plus dimensions or area per room, positioned at each room's label point and projected to screen.
   - Units in feet-inches (for example `14' x 12'`) or meters, following project units. Dimensions use the room's bounding width × depth, with area as an option.
   - Style options: font, size, a light text shadow or pill background, and on/off per room.
   - Labels are drawn as a **vector/canvas overlay composited after rendering**, never baked into the 3D textures.
5. **Decor and outdoor catalog** (extends prompt 5, procedural like the rest):
   - **Indoor:** potted plants (3 sizes, 4 species styles), rug patterns, wall art frames, table and floor lamps, decorative bowls and vases, a TV with wall unit, a gaming desk setup with RGB accent light, a bathroom spa tub, and gym equipment (treadmill, bench, rack).
   - **Outdoor, terrace, and balcony:** planter boxes, hedges, small trees, lawn and grass patches, deck flooring, a pergola, outdoor sofa set, outdoor dining set, sun loungers, a fire pit, a water feature or fountain, a small plunge pool (organic or rectangular shape with water material), garden path lights, a railing or glass balustrade, gates, and a parked car (2 styles) for when the design includes parking.
   - Add **outdoor zones:** a room type `outdoor` (balcony, terrace, garden) with no ceiling, an optional parapet instead of full walls, and outdoor floor materials (deck, stone, grass, water).
6. **"Auto-decorate" button:** for each room, add tasteful decor based on room type (plants in corners, rugs under seating, lamps by beds, art on long empty walls). Respect clearances, and apply it as one undoable batch.
7. **Export:** PNG at 1×, 2×, or 4× with labels composited, plus an option for no labels or a transparent background. Footer watermark: "Design render — indicative only".

## Part B — Local AI image enhancement (free, runs on the RTX 4060 Ti 16 GB)

1. **ComfyUI service in Docker** (extends prompt 14):
   - Add a `comfyui` service built from a repo Dockerfile:
     - CUDA-enabled PyTorch base image (pin exact tags).
     - ComfyUI cloned at a **pinned commit**.
     - GPU reservation like `ollama`, a `comfyui-models:/models` volume, and its port not published (internal network only).
   - Add a `comfyui-init` one-shot service that downloads these into the volume if missing, and logs total disk usage (expect about 10–15 GB):
     - Stable Diffusion XL base 1.0 from Stability AI's official Hugging Face repo.
     - An SDXL depth ControlNet (for example `diffusers/controlnet-depth-sdxl-1.0`).
     - Optionally, an SDXL canny ControlNet.
   - Document each model's license in `docs/HOSTING_WINDOWS.md`. Personal use is fine. The user is responsible for reviewing licenses for any other use.
   - Make the service optional with a compose profile (`--profile render`), so the app runs without it.
2. **GPU sharing (important on 16 GB):** the LLM (about 9–10 GB) and SDXL (about 7–9 GB) can't both stay loaded.
   - Extend the server's single-job queue from prompt 13 into one **GPU job queue** covering both AI design jobs and render jobs.
   - Before a render job, unload the Ollama model (a request with `keep_alive: 0`).
   - After a render, ask ComfyUI to free memory (its `/free` endpoint, unloading models).
   - The UI shows queue position and which job is running.
3. **Inputs rendered by the app**, all from the same camera:
   - The presentation color render without labels.
   - A **depth pass** (custom depth material, normalized, near = white).
   - An optional **line/edge pass** (normals or edge detection).
   - Upload them to ComfyUI through the app server.
4. **Workflow:** keep a versioned ComfyUI API-format workflow JSON template in `server/comfy/workflows/enhance_sdxl.json`:
   - img2img from the color render, plus depth ControlNet (and optionally canny), plus SDXL.
   - Parameters: prompt, negative prompt, denoise "creativity" (0.25–0.6, default 0.35), ControlNet strength (default 0.8), seed, and steps.
   - Resolution: 1024 on the long side by default, with an optional 1.5× upscale pass.
5. **Prompt builder:** generate a descriptive prompt from the project, which the user can edit before running.
   - It includes the view type, lighting look, room types, key materials, and style keywords (for example "luxury modern interior, top-down architectural cutaway render, warm dusk lighting, lush indoor plants, highly detailed, photorealistic").
   - It also includes a sensible negative prompt (text, watermark, distorted furniture, extra walls, blurry).
   - Add style presets: Modern Luxury, Warm Minimal, Classic, Tropical, Industrial.
6. **App server API:**
   - `POST /api/render/enhance` queues a job.
   - `GET /api/render/jobs/:id` returns status and progress, relayed from ComfyUI's websocket.
   - `GET /api/render/results/:id` returns the image.
   - Proxy only the ComfyUI endpoints you need (`/upload/image`, `/prompt`, `/history`, `/view`, `/free`, and the websocket). Apply body limits and timeouts.
7. **Labels after enhancement:** the AI garbles text, so enhancement always runs on the **unlabeled** render. The app then re-applies the crisp label overlay from Part A on top of the enhanced image, using the same camera projection.
8. **Results gallery:**
   - Store results in the `app-data` volume, linked to the project, with their parameters and seed.
   - A before/after slider comparing the exact render and the AI version.
   - "Re-run with new seed", download, and delete.
   - Every enhanced image carries a small corner badge: "AI-enhanced mood image — not to scale".
9. **Graceful fallback:** if the `render` profile isn't running, the Enhance button is disabled with a one-line explanation and the command to enable it. Part A still works fully.

## Acceptance criteria
- From the sample duplex, a user can produce a labeled dusk cutaway render like a magazine plan view in under 3 clicks, and export it at 2×.
- The path-traced still renders progressively and can be cancelled.
- With `docker compose --profile render up -d`, "Enhance" produces a photoreal image that keeps the room layout recognizable, with crisp correct labels re-applied.
- AI design jobs and render jobs never run on the GPU at the same time, and neither fails due to out-of-memory errors when queued back to back.
- Without the render profile, nothing breaks.
- Unit tests cover label projection and the prompt builder. An end-to-end test covers the presentation export; the AI enhancement is mocked in CI because CI has no GPU.

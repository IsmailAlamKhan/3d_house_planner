# Prompt 14 — Dockerize Everything (GPU-enabled) + Shared Project Storage

## Goal
Run the whole product with one command (`docker compose up -d`) on the Windows PC: the app server, the production web build, and Ollama with GPU acceleration. Docker becomes the **primary** way to run the app. Keep the native PowerShell scripts from prompt 13 as an alternative.

**Make this prompt idempotent.** If any of this already exists, update it rather than duplicating it.

## Tasks
1. **Shared project storage (server-side).** Projects currently live in each browser's IndexedDB, so a design made on one device doesn't show up on another. Fix that:
   - Add a REST API to the app server: `GET/POST /api/projects`, `GET/PUT/DELETE /api/projects/:id`, and `GET /api/projects/:id/versions` (the last 20 versions, with restore).
   - Store projects in SQLite (`better-sqlite3`) at `/data/app.db`. Validate every write with the same Zod schemas the frontend uses (move them to a shared package or folder).
   - Handle conflicts with optimistic concurrency: each project has an `updatedAt` / revision number. If two devices edit at once, show "This project was changed on another device" with options to reload or save as a copy.
   - The frontend uses the server as the source of truth and keeps IndexedDB as an offline cache. Edits made offline sync when the server is reachable again.
   - If `APP_PASSWORD` is set, the projects API requires the session cookie.
2. **Dockerfile** (multi-stage, in the repo root):
   - Build stage: `node:20-bookworm-slim` (pin an exact tag). Run `npm ci` and build the frontend and server.
   - Runtime stage: slim Node image with only production deps, the built `dist/`, and the server.
     - Run as a non-root user and expose port 8080.
     - Add a `HEALTHCHECK` that calls `/api/health`.
     - Make sure native modules (better-sqlite3) build or install correctly for the runtime image.
   - Add a `.dockerignore` (node_modules, .git, test output, local `.env`).
3. **docker-compose.yml**:
   - `app`: built from the Dockerfile, publishes `${PORT:-8080}:8080`, mounts the `app-data:/data` volume, reads `.env`, uses `restart: unless-stopped`, and depends on `ollama` being healthy. It sets `OLLAMA_URL=http://ollama:11434`.
   - `ollama`: the `ollama/ollama` image (pin a specific version tag, not `latest`), `restart: unless-stopped`, and the `ollama-data:/root/.ollama` volume so models survive restarts.
     - Request the GPU with `deploy.resources.reservations.devices: [{driver: nvidia, count: all, capabilities: [gpu]}]`.
     - **Don't** publish Ollama's port. It is reachable only on the internal compose network.
     - Add a healthcheck (`ollama list`).
   - `ollama-init`: a one-shot service using the same image that runs `ollama pull ${OLLAMA_MODEL:-qwen3:14b}` against the `ollama` service and then exits. The app works before the model finishes downloading, falling back to the offline generator and showing "Downloading AI model…" status from `/api/health`.
   - Named volumes: `app-data` and `ollama-data`.
4. **Variant for native Ollama:** add `docker-compose.host-ollama.yml`, which drops the `ollama` and `ollama-init` services and points the app at `OLLAMA_URL=http://host.docker.internal:11434`. Use it for anyone who prefers Ollama installed directly on Windows. Document `docker compose -f docker-compose.yml -f docker-compose.host-ollama.yml up -d`.
5. **Windows documentation** (update `docs/HOSTING_WINDOWS.md` with Docker first, native second):
   - **Prerequisites:** Docker Desktop with the WSL2 backend, and a current NVIDIA driver on Windows. WSL GPU support comes with the driver, so don't install a separate CUDA driver inside WSL.
   - **Verify the GPU:** run `docker run --rm --gpus all nvidia/cuda:12.4.1-base-ubuntu22.04 nvidia-smi`. Then, after startup, run `docker compose exec ollama ollama ps` during a generation and confirm the model shows as running on the GPU (100% GPU).
   - **Resources:** in Docker Desktop, give WSL2 enough memory (at least 16 GB) via `.wslconfig`, so a model that spills from VRAM can use system RAM.
   - **Auto-start:** turn on "Start Docker Desktop when you sign in". The `restart: unless-stopped` setting brings the containers back up.
   - **Updating:** `git pull && docker compose build && docker compose up -d`.
   - **Firewall and remote access:** same as prompt 13 (Private networks only, Tailscale for outside access, no port-forwarding).
6. **Backups:** add `scripts/backup.ps1` and `scripts/backup.sh`, which copy `/data/app.db` out of the `app-data` volume into a timestamped file (use the SQLite online backup API or `sqlite3 .backup`, never a raw copy of a live database), plus a matching restore script. Document a weekly Task Scheduler entry.
7. **CI:** extend the GitHub Actions workflow to build the Docker image, and run a container smoke test that starts the `app` service alone (no GPU in CI, so the offline generator is used) and checks `/api/health` and the project API.

## Acceptance criteria
- On Windows with Docker Desktop and an NVIDIA driver, `docker compose up -d` starts everything. The model downloads automatically, and AI generation runs on the GPU.
- A project created on one device appears on another device on the same Wi-Fi. Editing the same project on two devices at once triggers the conflict message instead of silently overwriting.
- Projects and models survive `docker compose down` and `docker compose up -d`.
- Ollama is not reachable from the LAN, only the app port is.
- Backup and restore are tested.

# Prompt for the AI agent on the Windows machine

Copy everything below the line into Claude Code (or another coding agent) running **on the Windows PC** with the NVIDIA GPU.

---

You are on a Windows 10/11 PC with an NVIDIA GPU. Repository: https://github.com/IsmailAlamKhan/3d_house_planner ("Duplex Designer": a free, local-first 2D/3D home design app with an optional local AI via Ollama).

The project was built on a Mac, so several things were **never run for real**. Your job is to set the app up here, verify those things, fix what is broken, and report honestly. Follow `docs/HOSTING_WINDOWS.md` (Docker first) and read `README.md`, `PROGRESS.md` and `docs/ARCHITECTURE.md` before changing anything.

## Rules
- Ask before anything that needs a password/admin rights, changes firewall or system settings, or installs software; tell me the exact command or download and why.
- Never put secrets in the repo. `.env` stays git-ignored; never publish Ollama's port (11434) to the network.
- Keep changes small. Do not refactor. If you change code, keep `npm run typecheck`, `npm run lint`, `npm test` and `npm run build` green. Commit with a plain message (no co-author or "generated by" trailers).
- Do not claim something works unless you ran it. If a step is skipped or fails, say so with the output.

## Tasks, in order
1. **Prerequisites.** Check/install (asking first): Git, Node 20+ (22 recommended), Docker Desktop with the WSL2 backend, the latest NVIDIA driver (no CUDA toolkit needed). Clone the repo.
2. **Docker GPU check.** `docker run --rm --gpus all nvidia/cuda:12.4.1-base-ubuntu22.04 nvidia-smi` must print the GPU. If not, diagnose (WSL2, Docker Desktop settings, driver) before continuing.
3. **Build and start.** `copy .env.example .env` (optionally set `OLLAMA_MODEL` to fit the GPU's VRAM: 8 GB → `qwen3:8b`, 12–16 GB → `qwen3:14b`; set `APP_PASSWORD`). Run `docker compose up -d --build`. This is the **first real build of the `Dockerfile`** (3 stages incl. native `better-sqlite3`) — if it fails, fix the Dockerfile/compose and explain the root cause. Wait for `ollama-init` to pull the model.
4. **Verify the stack.**
   - `http://localhost:8080/api/health` shows the app OK, Ollama reachable, model installed.
   - `docker compose exec ollama ollama ps` shows the model on **100 % GPU** while a generation runs (also watch `nvidia-smi`). Record the VRAM used and seconds per generation.
   - Open the app, create a project via the wizard, reload: it persists on the server. Open it from a second device/browser on the LAN (`http://<PC-ip>:8080`) and confirm it appears.
   - `docker compose down && docker compose up -d`: the project survives (volume `app-data`).
5. **Smoke test and backups.** Run `scripts/docker-smoke.sh` via Git Bash/WSL (or follow its steps by hand). Then `scripts\backup.ps1`, delete a project in the app, `scripts\restore.ps1`, confirm it returns.
6. **AI quality.** In the app's AI tab press *Test connection*, then generate:
   - "3 bedroom duplex with open kitchen" (apply it, check 2D and 3D look sane),
   - "luxury villa with pool, garden, 2-car garage, gym and sauna" on a **Villa on a plot** project (wizard: Villa, building 18 × 16 m, plot 34 × 42 m).
   Then run `npm install` and `npm run ai:eval` (needs Ollama reachable on 127.0.0.1:11434 — use the host-Ollama override or `docker compose port` only for your own test, never expose it). Report the summary lines (schema-valid, repair rounds, solver success, followed the brief, average seconds). Mac baseline with `qwen3:14b`: 15/15 valid, 15/15 solver, 12/15 followed brief, ~73 s average.
7. **Native option (second priority).** On a clean shell try `scripts\windows\setup.ps1` then `scripts\windows\start.ps1` (written but never run). Fix real bugs in the scripts; note Windows PowerShell 5.1 vs 7 differences.
8. **Desktop app (optional, ask first).** If I agree to install Rust + the Tauri prerequisites: `npm run tauri:build` (never run), and report the installer path or the errors.
9. **Full test suite on Windows.** `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npx playwright install chromium` then `npm run test:e2e`. Report any Windows-specific failures (path separators, line endings, `better-sqlite3` build, shell scripts) and fix them if small. Playwright's GPU-less tests are slow; if one is flaky, re-run it alone before judging.

## Deliverable
Update `docs/HOSTING_WINDOWS.md` with every correction you found (wrong commands, missing steps, real timings and VRAM numbers), add a short "Verified on Windows" section to `PROGRESS.md` (what you ran, on which GPU/driver/Docker version, what failed and how you fixed it, what is still unverified), commit, and give me a final report: a checklist of tasks 1–9 marked done / failed / skipped, with the key outputs, the GPU model, and the model/seconds-per-generation you measured.

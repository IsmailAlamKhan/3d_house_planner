# Prompt 12 — Hardening, Performance, Offline/PWA, Desktop Packaging & Deployment

## Goal
Make the app robust and fast, usable offline, installable, and easy to deploy. Optionally package it as a desktop app.

## Tasks
1. **Performance**
   - Profile the sample project and a stress project (two levels, 150 walls, 300 items).
   - Use instancing for repeated catalog items, merged static geometry per level where it's safe, frustum-friendly bounds, and lazy-loaded heavy modules (AI, export, PDF) via dynamic `import()`.
   - Move room detection and the layout solver to a Web Worker if they block the main thread for more than 50 ms.
   - Targets: initial load under 3 s on broadband (production build), and edit-to-render under 50 ms on the stress project at Medium quality.
2. **Robustness**
   - Add a global error boundary with "Recover last autosave".
   - Keep autosave snapshot history (the last 20 versions) with restore.
   - Show a corrupted-file import message.
   - Warn about unsaved work when closing the tab.
3. **PWA:** a service worker (vite-plugin-pwa) that caches the app shell and assets, so everything except cloud AI works offline. Add an install prompt and a manifest with icons.
4. **Desktop packaging (optional build target):** add a Tauri 2 config wrapping the same web build, with native file open/save dialogs for project files behind a small `platform` adapter (browser download/upload versus Tauri fs). Document `npm run tauri:dev` and `npm run tauri:build`. The web version must keep working unchanged.
5. **Testing:** raise unit test coverage on `model/`, `geometry/`, and `ai/` to at least 80%. Write Playwright end-to-end tests for the full journey: wizard → AI generate (offline) → edit → drag item → change material → walkthrough → export PDF and GLB.
6. **Deployment:**
   - A GitHub Actions workflow running lint, typecheck, tests, and build on every push, and deploying to GitHub Pages, or Netlify/Vercel config files as an alternative.
   - Make sure the base path works on GitHub Pages.
7. **Docs:** finish `README.md` (setup, features, AI provider setup and key privacy, desktop build, deployment) and `docs/ARCHITECTURE.md` (final module map and data flow diagram in Mermaid).

## Acceptance criteria
- Performance targets are met or documented with measurements.
- The app works offline (except cloud AI) after the first load and is installable.
- All tests pass in CI.
- `npm run tauri:build` is documented. If the Tauri toolchain isn't available in your environment, the config is still committed and validated as far as possible, and the gap is noted in `PROGRESS.md`.

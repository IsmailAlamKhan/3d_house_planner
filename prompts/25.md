# Prompt 25 — AI Design Copilot: Easy From Any Starting Point

## Goal
Make the AI the easiest way to design **any** villa or duplex, not just the reference one. Users can start from a sentence, a conversation, a reference photo, a hand sketch, a "like this one, but…" request, or a mood picture. Then they refine by talking to it.

All AI runs locally and free (Ollama `qwen3:14b` plus the vision model from prompt 19), through the GPU queue.

**Make this prompt idempotent.** Requires prompts 18, 19, and 24. Reuse the AI tab, edit operations with preview and undo, design options, and checks.

## Tasks
1. **One "Design with AI" entry point** (wizard first step and AI tab) with clear start options:
   - **Describe it:** free text, any length.
   - **Answer a few questions:** a guided interview (see 2).
   - **From a floor-plan picture:** the exact 1:1 path from prompt 19.
   - **From a sketch:** a photo of a hand-drawn plan, or rough boxes drawn in the app. Read it with the vision model as approximate positions, then improve with the optimizer while keeping the user's arrangement.
   - **Like this, but…:** start from any existing project, template, or the reference villa, and describe the changes ("like the reference villa but 2 storeys, 4 bedrooms, no gaming room, smaller pool").
   - **From mood pictures:** upload photos of interiors or exteriors the user likes. The vision model extracts style, materials, colors, and features, which go into the brief's style section (not the layout).
2. **Guided interview:** short, friendly questions with tappable chips plus free text, one question at a time, skipping anything the user already said:
   - plot or shell size and shape (or "draw it"), number of levels;
   - household (adults, children, elderly, guests, help);
   - must-have rooms and wishes (pool, garden, parking for N, gym, prayer room, home office…);
   - style; budget level (low, mid, high, luxury), which drives materials and finishes;
   - what matters most (light, privacy, open plan, storage).
   - It must take under 2 minutes, with "Skip, just design it" available at any time.
3. **The Design Brief:** every start option produces one editable, human-readable **Design Brief** card stored in the project. It covers the program (rooms with sizes), adjacency wishes, site features, style, budget, and priorities. It is the single input to the layout engine.
   - The user can edit it directly (add a room, change a size, toggle "must have" or "nice to have").
   - Changes to the brief can regenerate the design, keeping user-locked rooms.
4. **Bubble diagram step** (optional but on by default for new designs): show the program as draggable bubbles (size = area, lines = adjacency, color = zone) over the plot outline.
   - Dragging bubbles sets placement hints for the optimizer (prompt 24).
   - Non-technical users can arrange "kitchen here, bedrooms over there" before any walls exist.
5. **Agent loop with tools** (Ollama tool calling, with a JSON fallback for models without tools). The model never edits geometry directly; it calls tools that the app executes and validates:
   - `get_project_summary`, `get_brief`, `update_brief`;
   - `generate_candidates` (prompt 24), `apply_candidate`, `apply_edit_ops`;
   - `run_checks`, `get_scores`;
   - `place_items`, `set_materials`, `set_lighting_preset`;
   - `render_preview` (a quick raster thumbnail);
   - `ask_user` (a clarifying question with chips).
   - After generating or editing, the agent runs checks and **fixes its own failures** (up to 3 rounds) before showing the result.
   - Every change still goes through preview, Apply or Discard, and a single undo step.
6. **Conversational refinement:** a chat that knows the current selection and the brief.
   - Commands can be vague ("make it feel more open", "more light in the bedrooms", "make it cheaper", "add a room for my mother on the ground floor with its own bathroom"). The agent turns them into brief changes or edit operations and explains in one or two plain sentences what it changed and why.
   - **Quick chips** under the chat: "Bigger kitchen", "Add bedroom", "More light", "More privacy", "Cheaper finishes", "Make it luxurious", "Add pool", "Add parking".
   - **Point and ask:** select a room or item in 2D or 3D and type "change this to…".
   - **Compare:** "show me 3 versions of the master suite" creates design options to compare in the existing side-by-side view.
7. **Style and finishing in one step:** after layout, the copilot applies a style preset (Modern Luxury, Warm Minimal, Tropical, Classic, Industrial, or one from mood pictures). It sets wall, floor, and kitchen materials, furniture sets from the asset pack (prompt 20), landscaping, and a lighting preset, then auto-decorates. Each style also has a short budget note (finish level), linked to the cost estimate.
8. **Languages and voice:**
   - Briefs and chat work in **English and Bengali**. Detect the language, reason in English internally if that is more reliable for the model, and reply in the user's language.
   - **Voice input (optional):** a local Whisper service (for example whisper.cpp or faster-whisper in Docker, GPU through the queue, pinned version, profile `voice`) for speaking in English or Bengali. Don't use any cloud speech service. Hide the mic button when the service isn't running.
9. **Safety rails and transparency:**
   - Show a short "What I assumed" list after each generation (for example "Assumed 3.0 m ceilings, 2 cars, garden at the back") with one-tap corrections.
   - Nothing is applied without preview.
   - The copilot never claims a design is approved for construction; the existing disclaimer stays.
10. **Speed:** stream the agent's progress ("Reading your brief… Generating 3 layouts… Checking… Fixing Bedroom 3 daylight…"). The full first design from a brief should be ready in under about 90 seconds on the owner's PC. Measure it and record it.
11. **Evaluation** (`npm run eval:copilot`, extending the existing AI evals):
    - Use 40 scenarios: text briefs (including vague and Bengali ones), interview transcripts, 5 sketches, 5 "like this, but…" requests, 10 refinement commands.
    - Measure brief adherence (checked by code: requested rooms present, sizes within tolerance, features present), check failures after the self-fix loop, number of user turns needed, and time.
    - Record the results in PROGRESS.md and tune until brief adherence is at least 90% and there are no hard-check failures.
12. **First-time experience:** one example flow in the tour: "3-bedroom villa with garden and parking" → interview chips → bubble diagram → 3 candidates → pick → style → walk through. Also give the empty state a big "Design with AI" button.

## Acceptance criteria
- A user who has never seen the app can go from "I want a 4-bedroom villa with a pool for my family" to a furnished, styled, walkable 3D design using only chips, chat, and Apply buttons, in under 5 minutes.
- "Like the reference villa but 2 storeys and 4 bedrooms" produces a sensible 2-level design that keeps the reference's style and outdoor features.
- A photo of a hand sketch with 6 labeled boxes becomes a matching layout.
- A Bengali brief produces the same quality as its English translation in the eval.
- All changes are previewed and undoable, and the eval targets are met and recorded.

# Prompt 2 — Core Data Model, Store, Undo/Redo, Persistence

## Goal
Define the complete building data model and the store that every feature uses.

## Data model (`src/model/`)
Define TypeScript types and matching Zod schemas. Every entity has a string `id` (nanoid).

- **Project**: `id, name, units ('metric'|'imperial'), shell, levels[], walls[], openings[], rooms[], stairs[], items[], columns[], roofs[], materials (library overrides), settings, createdAt, updatedAt, schemaVersion`
- **Shell** (the existing apartment space): `footprint: Point[]` (polygon), `maxHeight`, `entrance: {position, direction}`, `fixedPlumbingPoints: Point[]`, `notes`
- **Level**: `id, name, index, elevation, floorToCeiling, slabThickness, visible, locked`
- **Wall**: `id, levelId, start: Point, end: Point, thickness, height?` (defaults to the level height), `type ('exterior'|'interior'|'partition'), materialInside, materialOutside, locked`
- **Opening**: `id, wallId, kind ('door'|'window'|'archway'), catalogId, offset` (distance along the wall from `start` to the opening center), `width, height, sillHeight, flip, swing ('left'|'right'|'none')`
- **Room**: `id, levelId, name, type` (living, kitchen, bedroom, bathroom, dining, study, utility, balcony, corridor, stair, other), `polygon: Point[], floorMaterial, ceilingMaterial, ceilingHeight?, doubleHeight: boolean`
- **Stair**: `id, fromLevelId, toLevelId, type ('straight'|'L'|'U'|'spiral'), position, rotation, width, riserHeight?, treadDepth?, railing: boolean`
- **Column**: `id, levelId, position, size {w,d}, shape ('rect'|'round'), structural: true, locked: true`
- **Item** (furniture or fixtures): `id, levelId, catalogId, position {x,y}, elevation, rotation, scale {x,y,z}, props (record)`
- **Roof / ceiling feature** (optional, minimal): `id, levelId, kind ('flat'|'skylight'|'void'), polygon`
- **Point**: `{x: number, y: number}`, where `y` is the plan's depth axis. In 3D, plan `(x, y)` maps to world `(x, elevation, y)`.

## Store (`src/model/store.ts`)
- A Zustand store with immer and zundo temporal middleware holds `project`, `selection` (ids plus type), `activeLevelId`, `tool`, and `viewMode`.
- Undo/redo covers project mutations only. Selection, camera, and tool changes are not part of history.
- Add typed operations in `src/model/ops/`: `addWall, updateWall, splitWall, deleteWall` (which also deletes its openings), `addOpening` (validates that it fits inside the wall length minus margins), `addLevel, reorderLevels, addRoom, updateRoom, addStair, addItem, moveItem, rotateItem, duplicate, deleteSelection`, plus a **batch/transaction** helper so multi-step edits (such as AI changes) undo as a single step.
- Write integrity rules as pure functions with tests: no zero-length walls, openings must not overlap on the same wall, and items stay within their level.

## Persistence
- Autosave to IndexedDB, debounced by 1 second. On load, show a project list (create, open, duplicate, rename, delete).
- Import and export project `.json` files, validated with Zod, and include a migration hook keyed on `schemaVersion`.
- Add a `createEmptyProject()` function and one **sample project**: a simple 2-level duplex inside a 10 × 12 m shell.

## UI wiring
- Undo/redo buttons work, with Ctrl/Cmd+Z and Ctrl/Cmd+Shift+Z (or Ctrl+Y).
- The Levels panel lists levels, lets the user set the active level, toggle visibility, add a level, and rename a level.

## Acceptance criteria
- The sample project loads, and its JSON round-trips through export and import unchanged.
- Undo/redo works across operations, and a batch of edits undoes in one step.
- Unit tests cover the schemas, operations, and integrity rules.

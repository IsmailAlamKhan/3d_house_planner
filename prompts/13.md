# Prompt 13 — Free Local AI & Self-Hosting on a Windows PC

## Goal
Run the whole product for free from one Windows PC (Ryzen 7 7700, RTX 4060 Ti 16 GB, 64 GB RAM): the web app, a small server, and a local LLM through Ollama. The household uses it from any device on the home network.

**Make this prompt idempotent.** If prompt 7 already exists with a different default provider, switch the default to local Ollama through `/api/ai` as described in `prompts/7.md`. Remove any hard dependency on paid APIs.

## Tasks
1. **App server** (`server/`, Node 20+, TypeScript, Fastify or Express):
   - Serve the production build (`dist/`) as static files, with SPA fallback.
   - `POST /api/ai`: proxy to Ollama (`OLLAMA_URL`, default `http://127.0.0.1:11434`).
     - Allow-list only `/api/chat` and `/api/tags`.
     - Limit request bodies to 1 MB and set a 180 s timeout.
     - Allow one generation at a time, queuing the rest, so the GPU isn't overloaded. The UI shows "Waiting for AI…" while queued.
   - `GET /api/health`: report app status and whether Ollama is reachable, plus the installed models.
   - Configure through `.env`: `PORT` (default 8080), `HOST` (default `0.0.0.0` for LAN access), `OLLAMA_URL`, `OLLAMA_MODEL`, and an optional `APP_PASSWORD`. If a password is set, use simple session-cookie login to protect the app on shared networks.
   - Ollama itself stays bound to `127.0.0.1`. Only the app server is exposed on the LAN.
2. **Scripts and docs for Windows** (`scripts/windows/`):
   - `setup.ps1`: checks Node and Ollama are installed, installs and builds dependencies, runs `ollama pull` for the configured model, and creates `.env` from `.env.example`.
   - `start.ps1`: starts the app server, checks Ollama is running (Ollama runs as a background app on Windows after install), and prints the LAN URL (for example `http://192.168.x.x:8080`).
   - Auto-start option: document running `start.ps1` at login through Task Scheduler, or optionally as a service with NSSM. Document both in `docs/HOSTING_WINDOWS.md`.
   - Firewall: document allowing inbound TCP on `PORT` for **Private** networks only.
   - Remote access from outside the home: document Tailscale as the recommended free option. Explicitly advise against router port-forwarding.
3. **Model guidance** in `docs/HOSTING_WINDOWS.md` and the in-app settings:
   - Default model: `qwen3:14b` (about 9 GB, fits fully in 16 GB VRAM with room for context).
   - Faster option: `qwen3:8b`.
   - Alternative: `gemma3:12b`.
   - Larger, slower option: `mistral-small` (24B), which is tight on 16 GB and may spill to system RAM.
   - Note that models must fit in VRAM to be fast. Spilling into system RAM works, thanks to the 64 GB, but is several times slower.
   - The model is a setting, not a code change. Any Ollama model that handles JSON schema output works.
4. **Prompt quality for small models:** add a test fixture set of 15 briefs (simple to complex, including vague ones like "something cozy for 2 people with a home office").
   - Add a script `npm run ai:eval` that runs them against the configured local model. It reports the schema-valid rate (after the single repair round), the solver success rate, and average time per generation.
   - Tune the system prompt and examples until the valid rate is at least 90% for `qwen3:14b`. Record the results in `PROGRESS.md`.
5. **UX for slower local generation:**
   - Show a progress state with elapsed time and a cancel button.
   - Use streaming from Ollama to show a "thinking…" indicator (still apply only the final, validated result).
   - "Generate 3 variations" runs sequentially and shows each result as soon as it's ready.

## Acceptance criteria
- On a fresh Windows machine with Node and Ollama installed, `setup.ps1` then `start.ps1` gives a working app reachable from a phone on the same Wi-Fi.
- AI generation works fully offline, with no internet and no paid API.
- `ai:eval` results are recorded.
- With Ollama stopped, the app still works and uses the offline generator.
